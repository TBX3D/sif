# v2.2 dispatch plan (lane map + waves)

*Local orchestration doc. Each lane runs as an opus-research -> sonnet-impl pair in
its own worktree off `v2.2-base`, local commits only, no push. Verification gate
per lane: `go build ./...`, `go vet ./...`, `go test -race -count=1 ./...`,
`golangci-lint run ./...` all green, then independent re-verify by the orchestrator.*

## Dependency graph

```
v2.2-base (= v2.1 integrated)
  |
  Wave 1 (parallel, disjoint files):
    - phase-a        fingerprint-type module + C2/C3/C5 proofs   [PLAN EXISTS -> impl only]
    - sigmoid-lift   lift copy-pasted sigmoidConfidence once      [research -> impl]
    - config         config file + named profiles (greenfield)    [research -> impl]
    - cve            cve enrichment (refs + versioning)            [research -> impl]
  |
  Wave 2 (after phase-a green; share internal/fingerprint/ or gate on proofs):
    - favicon-ssot   favicon single-source-of-truth               [research -> impl]
    - phase-b        dialect-merge bridge (gated on C2/C3/C5)      [research -> impl, C4 trap test first]
  |
  Wave 3:
    - detector-tuning FP/FN pass over favicon+cve+detectors        [research -> impl]
  |
  Integration: merge all green lanes into `v2.2`, gauntlet, tag snapshot.
  |
  v3 planning (separate spec+plan cycle): expression-DSL matchers, fuzzing/
  payload-sets, subcommands, resume/checkpoint. NOT started in v2.2.
```

## File-overlap ledger (why the waves are drawn this way)

- `phase-a` creates `internal/fingerprint/favicon.go`; `favicon-ssot` also rewrites
  it -> favicon-ssot is Wave 2.
- `sigmoid-lift` touches `internal/scan/frameworks/detectors/*.go` + `detect.go`;
  disjoint from phase-a's added test files -> Wave 1 parallel.
- `config` touches `internal/config/` + a new loader; `cve` touches the cve scanner
  only -> both disjoint, Wave 1 parallel.
- `phase-b` is the only user-facing loader change; gated on phase-a proofs.

## Wave 1 briefs

### phase-a (impl only)
Execute `docs/superpowers/plans/2026-07-07-dialect-unify-phase-a.md` task by task.
Sonnet implementer, full gauntlet, local commits.

### sigmoid-lift (research -> impl)
Research: the per-detector `sigmoidConfidence` is copy-pasted across
`internal/scan/frameworks/detectors/{waf,meta,frontend,cms,backend}.go` and
`confidence_test.go`; the v2 plan's `spike/unify-cutover` commit `ece16dd` lifts it
into `DetectFramework` once. Map the exact copies, design the single lift, and
require a differential test proving output is byte-identical before/after across
the detector corpus. Behavior-preserving refactor only.

### config (research -> impl)
Research: greenfield config-file + named-profiles system feeding the whole flag
surface from a file. Decide format (recommend toml, matching `template-example.toml`
already in the repo) and profile-precedence rules (flags > profile > file-default),
with justification. Map `internal/config/config.go` flag registration; design a
loader that a profile name selects. Keep zero-config behavior identical.

### cve (research -> impl)
Research: isolate the real `cve.go` change on `fix/cve-bare-major-version` (its
branch carries unrelated CI churn) and design the enrichment: reference URLs +
version-range handling (bare-major-version match fix). Map the cve scanner path and
its finding shape; do NOT change `Finding.Line()`.

## Wave 2 / 3 briefs (authored when their turn arrives)

- `favicon-ssot`: pick the Go map in `internal/scan/favicon.go` (or lift into
  `internal/fingerprint`) as the one source; point both the Go `Favicon()` lookup
  and the module `favicon` matcher at it; delete `favicon_demo_sync_test.go` once no
  duplication remains. Builds on phase-a's `internal/fingerprint/`.
- `phase-b`: the bridge. First task is the deferred C4 trap test (a non-root /
  confidence fingerprint must NOT be silently registered as a framework detector),
  then the one-dir/one-format cutover behind a seam with back-compat legacy read +
  deprecation log + root-path guard + confidence-wrap.
- `detector-tuning`: FP/FN pass via the detector-tuning skill over the new favicon
  and cve detectors plus the existing corpus.
